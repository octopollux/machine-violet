# Co-DM validation plan

2026-10-05. **Prepared, not executed.** These fixtures describe a proposed protocol, not existing engine interfaces. No runner or production changes are included. JSON syntax validation establishes only parseability. The design must pass deterministic protocol checks, actual-provider shadow replay, and paired live DM tests before a latency or cost claim is justified.

## 1. Deterministic protocol gate

Build an in-process engine test adapter with a scripted provider and controllable completion order. It must expose feed sequence, epoch, durable cursor, wake batch, write preconditions, public stream and logs, and volatile DM feedback injection. Run every case in [protocol-cases.json](fixtures/protocol-cases.json), including all delimiter split positions, malformed private blocks, duplicate delivery, rejected state changes, write races, crashes and rollback. No network is necessary.

Required assertions: zero private bytes in public output/public logs; no extra DM provider continuation caused by an embedded annotation; single ordered co-DM queue with no self-trigger; all pending complete exchanges in one user message per idle wake with intermediate events retained; immutable scene prefix until transition; no generic ordinary-turn flush; fresh mechanical reads and scene/lifecycle barriers actually await their required state. Compare authoritative final snapshot, public view, DM notes, cursor and accepted operation ledger against the withheld oracle. Every safety/correctness invariant must pass; one privacy leak, state loss or stale rollback write blocks progression.

At transition, stop new work for the old scene, drain both queues, freeze a final snapshot and cursor, then refresh the new prefix. A bounded replay proves the three ordinary post-transition turns and reload use the persisted state. Crash schedules cut before commit, after commit before cursor advance, and after feedback creation before injection acknowledgment. Re-delivery uses the original event/operation IDs. Rollback changes epoch and rejects outstanding writes from the abandoned epoch. A stale proposal is rejected or rebased with a fresh read, never silently applied.

Use existing `GameEngine` injection seams and the harness `waitForState`, `waitForNarrativeAtLeast`, `waitForEngineEvent`, `endSession` and `runProbe` patterns. Add observable co-DM queue/barrier predicates rather than guessing timers. Existing `waiting_input` alone is insufficient: assert accepted player input and separately measure input readiness. Image waits distinguish persisted, dispatch failure and provider failure. Existing golden tapes match bucket/ordinal rather than full prompt content and often mock helpers: passing `npm run golden:verify` cannot validate this architecture or changed prompt quality. Never hand-edit those recordings.

## 2. Live shadow replay: memory quality

Run the real Machine Violet agent/provider context and executable maintenance tool contracts, not a Codex delegate session with tens of thousands of unrelated instruction tokens. Feed each candidate the exact same frozen event stream, initial snapshot and identical scene boundaries, independent of what the candidate writes. The shadow state is isolated; it cannot alter the event source, DM transcript, tool outcomes or held-out oracle. Keep one persistent ordered conversation per run; do not make each stage a fresh agent. Supply initial context and new complete exchanges as the production design would, while keeping the scene prefix frozen.

The baseline scribe receives fixed original DM handoffs when replaying the captured workload, and the explicitly fixture-authored `baselineHandoff` strings for the synthetic scenario; it does not receive the raw co-DM feed under a changed contract. No unpaid helper may generate these handoffs during a run. Canonical facts are matched, while observation/access differences are intentional parts of the proposed architecture. Compare baseline tiny-context scribe (`gpt-6-luna`, small tier, record actual backend effort) with initial persistent co-DM `gpt-6.1-sol` at proposed **medium** effort. Verify wire model and reasoning effort, provider/runtime versions, cache settings and prompt hashes; tier labels alone are insufficient. A different-effort co-DM is a separate arm. Run five independent repeats per arm per frozen scenario with identical initial state; preserve failures and retries. Shadow tests score memory and actual maintenance costs, but cannot establish saved DM continuations or changed interactive pacing.

Score exact typed invariants from the oracle and blind human review of snapshots at every checkpoint. Report shared memory scores separately from candidate-only portrait/theme/passive-observation/feedback responsibilities: the baseline scribe lacks some of those capabilities and must not be penalized for them. Paired campaign costs include the baseline roles that currently perform those responsibilities. A completed interpretation is scored at its consumed event watermark: unseen future events cannot make an otherwise correct earlier result false. Separately measure lag and demand the final watermark at barriers. Stale-write validation uses per-target/field revisions or explicit fresh-read rebase, preserving unrelated legitimate changes rather than dropping every old batch. Reviewers receive public/private views separately and randomized arm labels. Rate privacy, contradictory current facts, preservation, identity/custody accuracy, useful feedback, and invented consequences. Count successful portrait requests and scene-image calls separately from tool intentions. Long-body preservation must use exact equality for untouched text, and a complete read before a body replacement; truncated previews are not safe replacement inputs. An ignored hook remains a dormant clue, not a player commitment. A useful freeform notice can enter DM context without a reply obligation or acknowledgment cascade.

## 3. Paired live DM A/B: experience and total cost

Baseline: Sol 6.1 medium DM plus Luna small-tier scribe. Candidate: same Sol 6.1 medium DM plus persistent Sol 6.1 medium co-DM. Keep backend/runtime/model version, DM effort, image mode, initial snapshots and player action script matched. Use actual DM agents and tool loops; replaying a canned DM transcript is the shadow arm, not this arm. Fixed dice/deck outcomes are an engine test adapter where feasible, documented explicitly. Once branches diverge, continue using common player intents only where coherent; report divergence and excluded/unmatched pairs rather than force invented equivalence.

Run five matched pairs, alternate A/B order, reset campaigns between runs, and include the baked seed opening plus at least two scenes, three ordinary turns after transition, and save/reload. Use two separately reported schedules: scripted fast-player stress (submit upon verified readiness) and controlled human-think-paced play (same predeclared player-decision pacing per paired action). Pacing is an experimental schedule, never a harness completion sleep. Freeze each schedule before running. Do not merge human deliberation into engine latency or treat the fast-player arm as normal play.

Measure monotonic timestamps from player submission arrival, before any freshness/admission wait, to first public text, narrative end, input ready and maintenance catch-up. Record acceptance separately so admission/queue blocking cannot disappear from the latency measurement. First public text excludes private block bytes. Post-narration tail = input-ready minus narrative-end; negative or unavailable observations require diagnostics. Record per-queue enqueue/start/finish sequence, lag, backlog high-water mark, batch sizes, and catch-up endpoint. At boundaries record complete end-to-end transition latency including both queue drains, snapshot work and refresh. Separate session start/reload from ordinary turns. Do not sum overlapping helper spans as wall time. Count DM API calls/continuations, private annotations, maintenance calls, retries and feedback injections.

For every role/helper attribute uncached input, cached input/cache write, public output, tool output and billable reasoning tokens using provider usage fields, recording unavailable categories as unknown. Reasoning may already be included in billed output: retain the breakdown without charging it twice. Cache-write accounting follows the actual provider billing semantics. Include summarizer, changelog, portraits and scene image costs; report usage and price source/date separately, with total dollars and uncertainty where billing cannot be resolved. Compare total campaign cost including catch-up and boundaries, not only foreground cost. Narrative-only response speed can hide more expensive background work.

Decision gates: all deterministic invariants pass; zero live privacy leaks, lost authoritative values or abandoned-epoch writes; final barrier catches up fully; no persistent ever-growing backlog; no critical blind-review defect. Scene drains may be slower, as accepted in the design discussion: report their complete distribution and catch-up behavior rather than impose a speed-regression threshold. Proposed candidate signals, not user-approved pass criteria, are a 10% median paired ordinary input-ready improvement and at least 95% frozen memory checks. Report total cost as a lower-cost win, a quantified priced tradeoff, or inconclusive evidence; the user chooses whether the measured tradeoff is worthwhile. With five pairs, percentile and uncertainty estimates are exploratory: report all paired observations and bootstrap intervals, and never convert a wide interval into a pass. Narrative quality must show no material blind-review regression. Do not trade correctness for speed.

For exploratory interactive live play, the coordinating agent follows the repository `/play` workflow turn by turn; do not substitute a delegated or scripted player. A predeclared repeatable pass/fail sequence belongs in a one-shot `runProbe` using observable waits. The paired experiment must declare which mode it uses; no live calls are authorized or made by preparing this document.

## Experimental shadow runner (2026-10-05)

`npx tsx packages/test-harness/bin/co-dm-shadow.ts` validates fixture loading and writes a manifest without making provider calls. Run an explicitly isolated actual-provider replay with:

```powershell
npx tsx packages/test-harness/bin/co-dm-shadow.ts --live --arms baseline,candidate --repeats 1 --output .batch-runs/co-dm-shadow-first
```

`--repeats` accepts 1 through 5. `--config` points to an existing connection-store directory; credentials are loaded through the engine connection loader and never emitted. Each arm/repeat gets a new SQLite database. Fixture aliases map reproducibly to allocated canonical UIDs, including explicit reference values. The oracle stays evaluator-only. Candidate stages 2–4 wake together; baseline receives the fixture-authored handoffs under its current contract. The candidate uses a continuing conversation and resets only at the scene transition.

This initial staged runner measures **knowledge maintenance only**. It supplies production knowledge tools to the continuing candidate, rather than silently emulating unavailable presentation tools. Portrait/theme work, spontaneous-feedback quality and prose invariants are explicitly unscored, and no aggregate quality pass is claimed. Stage snapshots, tool ledger and continuing context contain invented private fixture content and remain private files under ignored `.batch-runs`. `calls.json` contains hashes, model/effort, monotonic spans and normalized usage rather than prompts. Scoring checks canonical identity references, redirects, collection preservation, exact archive preservation and public secret exclusion. Scene reload checks SQLite snapshot equality. It cannot establish player input latency or saved DM continuations.

Optional `--prices <path>` accepts a JSON object with a `source` provenance string and model-keyed `{ "input": 2, "cached": 0.1, "write": 2.5, "output": 10 }` rates per million tokens. For OpenAI usage, cached input is subtracted from total input, and reported reasoning is a subset of output: it is retained without being charged again. Absent a validated matching rate, dollars remain unknown. Cache writes are retained and priced separately when reported by this backend. `co-dm-cost.ts <run-directory>` postprocesses both runners with official Sol/Luna rates verified on 2026-10-05; it marks standard-tier/nonregional assumptions and preserves unpriced calls. Provider failures are retained without credential-bearing error text. These are runner instructions, not executed live results.

The companion `packages/test-harness/bin/co-dm-paired.ts` prepares a declared fast-player workload from the recorded Long Patience opening checkpoint. `--prepare` archives the immutable source commit into new `.batch-runs` directories and boots both real GameEngine arms offline, rejecting any attempted provider inference. Plain invocation only writes a manifest. `--live --pairs 1` runs the declared seven player intents with a scene boundary after intent four (a natural cut satisfies it; otherwise the runner requests a cut), then three ordinary turns, end/reload, and a declared additional post-reload input; `--pairs` accepts 1–5 and alternates arm order. Initial independent branch divergence requires review/exclusion, and any explicit cut is an experiment control. Boundary-bearing inputs are recorded separately from ordinary input-ready comparisons. It uses existing captured campaign fiction and predeclared observation intents, never invented DM responses.

Production FileIO, SQLite, PC sheets, bundled rules, persisted mechanics and conversation are restored in each isolated copy. DM effort is explicitly medium for both arms; all actual provider request models/efforts and helper calls are retained. Images are disabled in both arms and that omission is recorded: this selected workload cannot establish complete image/portrait campaign costs. Every player arrival is recorded before `processInput`, with acceptance, first public text, narrative completion, readiness and return timestamps separately. Ordinary turns do not drain maintenance. Queue cursor/backlog snapshots and monotonic enqueue/start/finish/error/commit events are retained. Finish marks provider/tool work completion; commit marks durable cursor acknowledgment. Candidate turn catch-up is assigned by the committed exchange IDs, without ordinary drains. Baseline catch-up remains unavailable where its existing lane exposes no corresponding queue event; it must not be inferred from input readiness. Boundary/session/reload spans include observable awaited work. Raw requests/responses and narrative/tool traces are private ignored artifacts; public call and timing ledgers contain model/usage and counts. These limits preclude a complete latency/cost win declaration from the first smoke run.

The paired runner restores all directories from production `campaignDirs()` after Git archive extraction, since Git omits empty directories. Engine error callbacks retain sanitized private diagnostics and invalidate the arm; a caught engine error cannot silently produce a successful run. `--think-ms 30000` applies a predeclared decision schedule anchored to actual readiness. The schedule delays player arrival, never infers engine completion, and think time is excluded from arrival-based latency. Plain `--prepare` validates restoration without inference. The initial pilot is retained separately as invalid lifecycle evidence due missing session-recap directories and a redundant forced cut after a natural candidate cut; it is not a clean paired success.

Current runners freeze data-only request snapshots and request/system hashes before provider invocation, omit local dispatch callbacks, and clone returned results/usage. Earlier paired runs retained mutable request references and computed hashes after invocation; their saved arrays cannot prove exact dispatch-time message chronology. The pilot report identifies this limitation. Machine homes are isolated per arm, and final maintenance-settle errors invalidate completion. These changes improve subsequent evidence capture without retroactively upgrading older recordings.
